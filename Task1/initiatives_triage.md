**Триажер:** Solution Architect

|---|-----------|----------|--------|--------|---------|--------------------------|---------------------------|

| **8** | Предсказывать, какие клиенты собираются уйти в другой банк | Классификация (уйдет/останется) | Табличные (активность, комиссии, жалобы, история) | **ML-кандидат** | **✅ БЕРЕМ (доп. инициатива #2)** | Есть историческая разметка (ушел/остался), есть признаки (снижение активности = сигнал). ## Ключевые выводы

### Не про ML (не задачи архитектора)
- #7 (BI): Дашборд, решается Tableau/Grafana
- #16 (шаблоны): Jinja2 + PDF, не нужна LLM
- #17 (блокчейн): Хайп, Postgres дешевле

### Заблокировано (нужны юристы перед началом)
- #11, #12: Регулируемые виды деятельности (лицензии, ответственность)
- #9, #10: Персональные данные (согласие, регуляторика)

### Требует уточнения бизнеса
- #3: Как часто меняются тарифы? (правило или LLM как GPT-4o?)
- #15: Нужна ли модель или достаточно ARIMA?
- #18: Насколько критична точность извлечения при использовании Claude/Qwen?

### ML-кандидаты (из них выбираем 3 для глубокой работы)
✅ **#1 — ФЛАГМАН** (выявление подозрительных операций)
✅ **#4 — Прогноз просрочки** по портфелю
✅ **#8 — Прогноз оттока** клиентов
⚠️ **#15** — Прогноз нагрузки на кол-центр (нужна проверка: модель или ARIMA?)

## Переход к Decision Matrix

Для каждого из 3 ML-кандидатов (#1, #4, #8) нужно оценить:
- Наличие данных (есть ли примеры? достаточно ли?)
- Сложность ML (табличные vs текст vs видео)
- Регуляторные ограничения
- Приоритет бизнеса
- Взаимодействие с флагманом

**Результат:** Выбираются ровно 3 инициативы (1 флагман + 2 доп), для которых будут созданы паспорта и ADR в Task 2-4.
