### 📐 Этап 2: Размерность — Train/Val/Test разделение (dimensioning.md)

**Проблема:** Как разделить 480K операций без утечек?

**Решение:** Time-based split (хронологическое разделение)

```
TRAIN:  Jan 2022 - Aug 2022  (320K операций, 640 fraud)
VAL:    Sep 2023 - Oct 2023  (80K операций, 160 fraud)
TEST:   Nov 2023 - Dec 2023  (80K операций, 160 fraud)
```

**Проверки утечек:**
- ✅ Счета не пересекаются между наборами
- ✅ Параметры нормализации считаны ТОЛЬКО по TRAIN
- ✅ Нет операций из будущего в обучение
- ✅ Дисбаланс класса 0.2% сохранен во всех трех наборах

**Результат:** Готовые файлы `train.parquet`, `val.parquet`, `test.parquet` с нулевой перекрестной утечкой.

### 🤖 Этап 3: Выбор модели (model_selection.md)

**Кандидаты на рассмотрение:**

| Модель | Диагностика (20 примеров) | TRAIN → VAL | F1 | Inference | Выбор |
|--------|---|---|---|---|---|
| **LightGBM** | 19/20 ✅ | Precision 72%, Recall 85% | 0.78 | 5ms | ✅ ВЫБРАНА |
| **XGBoost** | 18/20 ✅ | Precision 70%, Recall 83% | 0.76 | 12ms | ⚠️ Медленнее |
| **LogReg** | 12/20 ❌ | Precision 60%, Recall 70% | 0.65 | 1ms | ❌ Слабая |

**Конфигурация LightGBM для PRODUCTION:**

```python
{
    'objective': 'binary',
    'metric': 'binary_logloss',
    'max_depth': 7,
    'learning_rate': 0.1,
    'scale_pos_weight': 480,  # КЛЮЧЕВОЙ: компенсация дисбаланса
    'feature_fraction': 0.9,
    'bagging_fraction': 0.8,
    'num_boost_round': 200,   # С early stopping на 20
}
```

**Метрики на TEST (hold-out):**
- **Precision:** 71% (из 100 помеченных, 71 правильно)
- **Recall:** 84% (поймали 134 из 160 fraud)
- **F1:** 0.77 (балансовая метрика)
- **ROC-AUC:** 0.90 (отличная разделяющая способность)
- **Specificity:** 99.7% (мало ложных алертов)

**Интерпретируемость:** Top-10 признаков (SHAP):
1. Foreign country (трансграничная) → 0.32 impact
2. Multiple operations same day (дробление) → 0.28
3. Amount deviation (аномалия суммы) → 0.24
4. Memo length (длинное пояснение) → 0.18
5. New account (холодный старт) → 0.15
6. Counterparty risk score (контрагент в сером списке) → 0.14
7. Industry mismatch (ОКВЭД не совпадает) → 0.12
8. Weekend operation (выходной) → 0.09
9. Amount % of balance (сумма % от баланса) → 0.08
10. Previous alerts (история алертов) → 0.07

## Финальный рецепт для PRODUCTION

### Инфраструктура

```
Language: Python 3.11
Library: LightGBM 4.3.0
Format: ONNX (Open Neural Network Exchange)
Model size: ~2 MB
Latency SLA: <100ms на p95
Throughput: 1000+ predictions/sec (50% CPU)
```

### Данные

```
Training set: 320K операций (Jan-Aug 2022)
Fraud rate: 0.2% (640 examples)
Features: 50+ признаков (табличные + текст операции)
Normalization: mean/std от TRAIN только
```

### Мониторинг в Production

```
Метрика                   Red Line    Yellow Line   Частота проверки
─────────────────────────────────────────────────────────────────
Precision                 < 60%       < 70%         Moving window 7дн
Recall                    < 70%       < 80%         Moving window 7дн
ROC-AUC                   < 0.85      < 0.88        Moving window 7дн
Distribution drift (KS)   > 0.15      > 0.10        Weekly
Inference time            > 200ms     > 150ms       Realtime
Model version             Outdated    > 6 months    Manual check
```

### Триггеры пересчета

**STOP модель, если:**
- Precision упал < 60% (слишком много ложных алертов)
- Recall упал < 70% (слишком много пропусков)
- Новая версия LightGBM вышла

**Пересчет планово:**
- Каждые 6 месяцев (Mar 2025, Sep 2025)
- При изменении регуляторики (новые AML-требования)
- Когда появится новый продукт (расчеты, форфейтинг и т.д.)
